# Project Autopsy

프로젝트 계획의 가능한 실패 경로를 조사하고, 계획을 고친 뒤 위험의 변화를 비교하는 로컬 웹 앱이다. 현재 구현은 [v0.1 PRD](PRD.md)와 [기술 설계](TECH_DESIGN.md)를 기준으로 한다. 다음 버전의 범위는 [v0.2 PRD](PRD-v0.2.md)에 정리했다. 현재 확인된 동작과 한계는 [검증 기록](VERIFICATION.md)에 정리했다.

## 실행

Python 3.11 이상이면 추가 패키지 없이 실행할 수 있다.

macOS에서는 [start.command](start.command)를 더블클릭하면 데모 서버가 시작되고 브라우저가 열린다. **열린 터미널 창을 닫으면 앱도 종료된다.** 다시 접속할 때 연결 오류가 나면 `start.command`를 다시 실행한다.

```bash
cd project-autopsy
python3 -m project_autopsy --mode demo
```

브라우저에서 `http://127.0.0.1:8765`로 접속한다. 데모 모드는 모델 호출 없이 흐름을 확인하며, 사용한 실패 사례 12개는 모두 **가상 샘플**이다. 분석 내용도 규칙 기반 시연 결과로 표시된다.

실제 모델로 분석하려면:

```bash
export OPENAI_API_KEY='...'
python3 -m project_autopsy --mode live
```

기본 모델은 `gpt-4o-mini`다. `OPENAI_MODEL` 환경 변수로 바꿀 수 있다. Live 모드에서는 입력 계획과 검색된 가상 사례가 OpenAI API로 전송된다. API 키는 브라우저로 전달하지 않는다.

## 사용 흐름

1. 새 프로젝트를 만들고 계획을 적는다. 예시 버튼으로 시연 데이터를 불러올 수 있다.
2. 추출한 사실·가정·정보 공백을 확인하거나 수정한다.
3. 사망 보고서를 생성한다. 모든 미래 사건은 가상 시나리오이고, 사례 출처가 카드에 표시된다.
4. 보고서가 고른 핵심 질문 하나에 답하거나 `아직 모름`을 선택한다. 답변은 미검증 정보로 표시되고, 수정안은 저장 전 편집할 수 있다.
5. 수정안을 승인해 새 버전으로 저장하면 재분석과 전후 비교가 실행된다. 질문을 건너뛰고 직접 계획을 고칠 수도 있다.
6. 관련 없는 위험은 이유를 적고 제외할 수 있다.

프로젝트 데이터는 `data/autopsy.sqlite3`에 저장된다. 이 파일은 Git 추적 대상에서 제외된다.
테스트처럼 별도 데이터베이스를 쓰려면 `--database /path/to/test.sqlite3`를 지정한다.

## 현재 한계

- 사례 라이브러리는 기능 검증을 위한 가상 샘플만 포함한다. 실제 프로젝트의 실패 가능성이나 확률을 검증한 결과가 아니다.
- 비교 결과는 변경된 계획에 근거한 판단이다. 조치를 실제로 완료했는지는 확인하지 못한다.
- 공개 출처 사례, 사용자 문서 업로드, 프로젝트 삭제와 계정 기능은 다음 단계다.
